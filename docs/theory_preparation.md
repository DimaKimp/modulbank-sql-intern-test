# Подготовка к собеседованию: базы данных и SQL

Материал по теоретической части исходного задания «Тестирование стажёров: базы данных и SQL». Это **ответы для подготовки к интервью**, а не отдельное требование написать код.

## 1. Базовые понятия

**Что такое СУБД и зачем она нужна? Почему не хранить всё в Excel или файлах?**

Система управления базами данных (СУБД) позволяет хранить и обрабатывать структурированные данные, организовывать многопользовательский доступ, контролировать целостность, выполнять запросы и управлять транзакциями. В отличие от обычных файлов и таблиц Excel, СУБД предоставляет ограничения, индексы, права доступа, резервное копирование, управление конкурентными изменениями и более надёжную работу с большими объёмами данных. Excel полезен для небольшого анализа, но не заменяет СУБД для критичных многопользовательских операций.

**Какие СУБД бывают?**

- Реляционные: PostgreSQL, MySQL, Oracle Database, Microsoft SQL Server — таблицы и связи, SQL.
- Документные: MongoDB — документы, часто в формате, похожем на JSON.
- Ключ–значение: Redis — быстрый доступ по ключу.
- Колоночные аналитические: ClickHouse — эффективная обработка больших аналитических выборок.
- Графовые: Neo4j — связи в виде графа.

Классифицировать можно также по архитектуре (встроенные, клиент-серверные, распределённые), назначению (OLTP / OLAP), лицензированию (открытые и коммерческие).

**Что такое реляционная модель?**

Данные представлены отношениями (таблицами), состоящими из строк и столбцов. Для идентификации записей используют ключи, а связи между таблицами обычно реализуют внешними ключами. Запросы строятся на операциях выборки, соединения, проекции и других операциях реляционной алгебры.

## 2. Ключи и связи

**Первичный и внешний ключ**

- **Первичный ключ (PRIMARY KEY)** однозначно идентифицирует строку таблицы, уникален и не допускает `NULL`.
- **Внешний ключ (FOREIGN KEY)** ссылается на ключ родительской таблицы и обеспечивает ссылочную целостность. Внешний ключ может повторяться; допустимость `NULL` определяется ограничениями столбца.

**Типы связей**

- Один к одному: строке A соответствует не более одной строки B. Например, `users` и `user_profiles` с уникальным внешним ключом.
- Один ко многим: клиент может иметь несколько счетов (`clients` → `accounts`).
- Многие ко многим: создаётся связующая таблица, например `student_courses(student_id, course_id)` с двумя внешними ключами и составным первичным ключом.

## 3. Нормализация

**Что такое нормализация?**

Организация данных для уменьшения избыточности и исключения аномалий вставки, изменения и удаления.

- **1НФ:** значения в ячейках атомарны в рамках выбранной модели, нет повторяющихся групп столбцов.
- **2НФ:** таблица находится в 1НФ, а неключевые атрибуты полностью зависят от всего кандидатного ключа (существенно для составных ключей).
- **3НФ:** таблица находится в 2НФ; нет нежелательных транзитивных зависимостей неключевых атрибутов от ключа.

**Когда уместна денормализация?**

Для ускорения часто выполняемых чтений и аналитических запросов: например, хранение рассчитанного итога или заранее подготовленной агрегированной таблицы. Минусы — дублирование данных, дополнительные обновления и риск несогласованности; следует обосновать измерением производительности.

## 4. SQL и работа СУБД

**WHERE и HAVING**

`WHERE` фильтрует исходные строки до группировки; `HAVING` фильтрует группы после `GROUP BY`. Пример:

```sql
SELECT client_id, COUNT(*) AS account_count
FROM accounts
WHERE closed_at IS NULL
GROUP BY client_id
HAVING COUNT(*) > 2;
```

**Виды JOIN**

- `INNER JOIN` — только совпавшие строки обеих таблиц.
- `LEFT JOIN` — все строки левой таблицы и совпадения из правой; при отсутствии совпадения поля правой стороны — `NULL`.
- `RIGHT JOIN` — симметрично левому.
- `FULL OUTER JOIN` — все строки обеих таблиц.
- `CROSS JOIN` — декартово произведение.
- `SELF JOIN` — соединение таблицы с самой собой (например, сотрудники и руководители).

**DELETE, TRUNCATE и DROP**

- `DELETE FROM table WHERE ...` — удаляет выбранные строки; без `WHERE` — все строки.
- `TRUNCATE TABLE table` — быстро очищает таблицу целиком, без фильтра по строкам. Особенности транзакционности и сброса идентификаторов зависят от СУБД; в PostgreSQL `TRUNCATE` можно откатить в транзакции.
- `DROP TABLE table` — удаляет сам объект таблицы вместе с данными и определением.

## 5. NULL, индексы и транзакции

**Что такое NULL?**

Маркер отсутствующего или неизвестного значения; не эквивалентен нулю или пустой строке. Сравнения `= NULL` не работают как обычное равенство: используйте `IS NULL` / `IS NOT NULL`. Для замены отсутствующего значения подходит `COALESCE(value, 0)`. Агрегат `COUNT(column)` не учитывает `NULL`, а `COUNT(*)` считает строки.

**Что такое индекс?**

Дополнительная структура данных для ускорения поиска, фильтрации, соединений и иногда сортировки. В PostgreSQL по умолчанию широко используется B-tree. Минусы: место на диске и затраты на поддержку при вставках, изменениях и удалениях. Индекс не гарантирует ускорение каждого запроса: всё зависит от условий и плана выполнения.

**Что такое транзакция?**

Группа операций, выполняемая как логическое целое. Свойства ACID: атомарность (Atomicity), согласованность (Consistency), изоляция (Isolation) и долговечность (Durability). Например, перевод денег должен одновременно списать сумму с одного счёта и зачислить на другой; при ошибке транзакция откатывается (`ROLLBACK`), а при успехе фиксируется (`COMMIT`).
